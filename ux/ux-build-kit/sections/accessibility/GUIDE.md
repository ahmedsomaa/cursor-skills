# Accessibility

## Produce

System-wide inclusive rules components and patterns reference — do not paste the full checklist into every component.

- Contrast, keyboard, focus, touch targets, labels, error identification, screen readers, reduced motion, zoom/scaling.
- Build into foundations and components; `system.json` `accessibility` summarizes non-negotiables.

## Represent

`accessibility.html`:

1. What / Why / When
2. Per topic: **Rule → good example → bad example**
3. System checklist (contrast, keyboard, focus, touch, labels, errors, SR, reduced motion, zoom)
4. Do / Don't

Components and patterns link here for shared a11y behavior.

## Do / Don't

**Do:** Visible focus; keyboard paths; contrast; not color-alone status; meaningful errors; reduced motion; zoom.

**Don't:** A11y-only-as-final-checklist; hide focus; placeholder-as-label; assume only engineers own a11y.
