# Governance

## Produce

How this product’s system stays coherent — ownership, proposal, review, naming, versioning, deprecation. Lightweight enough that teams use it. `system.json` `governance` states ownership and the contribution bar.

## Represent

`governance.html` — process page, not a token gallery:

1. What / Why / When
2. Lifecycle: Proposed → Exploration → Review → Approved → Documented → Adopted → Maintained → Deprecated
3. Contribution checklist before adding a component or foundation change
4. Naming, versioning, migration notes for breaks
5. Do / Don't

## Do / Don't

**Do:** Clear ownership; review criteria; sync docs with the system; record decisions; deprecate with guidance.

**Don't:** Arbitrary variants; Figma-as-only-truth; forever-deprecated leftovers; casual foundation breaks; bureaucracy that makes people avoid the system.
