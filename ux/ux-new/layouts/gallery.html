Gallery Layout

Agent guide for the Gallery docs chrome. Details are not copied into design/. Build from gallery.jobs.md (staged reads); open a single #wf-* here only if needed. Wireframes = IA/placement only — ship a finished unique handbook. Example: Mantine UI (card/tile gallery for subsections). No navbar — home uses three page sections (Brief, Design system, Screens); cards open subsections.

1. Details

Name
Gallery Layout
Examples
Mantine UI — card/tile gallery for subsections (not a docs navbar)
Style
Docs chrome corners (docs.json style). Wireframes: style.html — square · squircle · pill. Apply to cards and the theme control.
Fonts
This agent-guide HTML uses Inter. Product docs: typography.html (pairings that list gallery). Docs fonts = handbook default (incl. principles / patterns / icons / themes prose). Design-system typography only inside UI samples, typography specimens, storyboards, and screens.
Icons
None in docs chrome — text labels only. Product Foundations / screens may use Lucide; never mix icon-nav with text-only nav.
Description
No navbar / main-nav strip. Header is one row, two columns: long column = system title + “Design handbook” subtitle; small column = theme toggle. Home (index.html) stacks three page sections — Brief, Design system, Screens — each with a section heading and a card grid for its subsections. Cards open nested pages (still no navbar; optional crumb + page title). Design system cards → Foundations subcategory cards → section specimen. Screens cards → feature → Storyboard / Designs cards → screen + states.
