# UX evaluation dimensions

Shared checklist for [ux-evaluate](../ux-evaluate/SKILL.md). [ux-prioritize](../ux-prioritize/SKILL.md) may reuse severities and impact language.

Evaluate from a **product/UX** perspective, not visual taste. For each dimension, note what works and what does not. Justify with UX principles and this product’s context.

## Dimensions

1. **User flows** — end-to-end task completion, dead ends, unnecessary steps  
2. **Information architecture** — grouping, labeling, findability  
3. **Navigation** — wayfinding, orientation, back/exit paths  
4. **Interaction design** — controls, affordances, gestures, destructive actions  
5. **Information hierarchy** — what reads first, scanability  
6. **Content / terminology** — clarity, consistency with product vocabulary  
7. **Forms and input** — labels, validation, defaults, effort  
8. **Feedback and system states** — loading, empty, error, success, progress  
9. **Cognitive load** — memory, competing CTAs, complexity at each step  
10. **Accessibility** — focus, labels, contrast, targets, semantics, keyboard  
11. **Visual hierarchy** — emphasis, grouping, density  
12. **UI consistency** — patterns, components, spacing, alignment across screens  

## Finding types (classify each)

- **Usability problem** — blocks or meaningfully harms task success  
- **Minor polish** — visual/craft nits without clear task impact  
- **Product/UX opportunity** — improvement that is not a broken path  
- **Personal preference** — taste only; do not treat as a required fix  

## Finding fields

For every finding document:

| Field | Meaning |
| --- | --- |
| Where | Screen, flow, or component |
| What | Current behavior |
| Why | Why it is problematic (principle + context) |
| Who | Roles / users affected |
| Impact | User and/or business impact |
| Opportunity | Direction for improvement (not a full redesign) |
| Type | usability / polish / opportunity / preference |
| Severity | critical / high / medium / low |
